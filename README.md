漫游时左下角显示体力条：干地连续快走约 8.7 秒耗尽，涉水更快；停止消耗 0.9 秒后恢复，静止恢复快于步行。耗尽后维持普通步行，恢复到 30% 且松开 Shift 才能再次快走。原地按住 Shift 或顶墙不会耗体力；跳跃消耗 10%。退出漫游、页面失焦或切后台会清空移动按键，后台不累计移动或体力。

## 分部位材质与法线贴图

当前建筑使用五类可无缝重复的 PBR 表面；其中四类沿用原创贴图，灰泥接入经浅色涂装校准的 Poly Haven CC0 素材，保持低饱和的旧泳池色调：

- 池底及水下墙面：8 × 8 cm 青绿小马赛克，细砖缝与轻微釉面起伏。
- 墙裙、柱脚和高层栏墙：16 × 32 cm 象牙色釉面砖；釉面墙裙至所在房间基面以上 1.56 m，其上接 8 cm 石材压顶，釉面内有窄色带。墙和立柱统一按各自基面对齐。
- 上部墙体、顶棚：暖色细灰泥，微小抹痕与颗粒法线，较高粗糙度。
- 台阶、窄池沿、压顶及拱圈：浅色石灰岩，120 × 60 cm 错缝板材与细孔隙。
- 宽阔的干区平台和高层步道：细颗粒水磨石，少量低饱和绿色与暖色骨料。

材质标记附在已有合并面片上，保持原空间批次和实例化结构。水下、墙裙与灰泥的分界在片元着色器中按实际高度决定，顶棚底面直接指定灰泥。圆柱用连续圆周 UV，釉面/马赛克按完整砖数环绕；其余墙地面使用世界坐标米制铺贴，避免各面随机拉伸。

素材目录为 `public/assets/pool-surfaces/`，共 25 张 PNG：每套含颜色、OpenGL +Y 法线、粗糙度、16 位高度图，以及运行时打包图。法线来自同一份毫米级高度数据，颜色与凹凸位置对应；高度图供后续编辑使用，当前没有启用几何置换。马赛克、釉面砖、石灰岩的法线/粗糙度/高度细节为 2048²，灰泥与水磨石细节为 1024²；颜色图保持 1024²，灰泥颜色为 512²。

运行时只加载每套颜色与打包细节图：打包图 RGB 是法线 XYZ，A 是粗糙度；颜色按 sRGB 读取，细节图按线性数据读取。大部分片元只采样所选的一套颜色/细节；水下马赛克与釉面砖之间的 7 cm 窄带混合两套颜色、法线与粗糙度，避免硬切。使用显式梯度、多级渐远和最高 16 倍各向异性过滤（以设备能力为限）。10 张运行时 PNG 共约 4.03 MiB，GPU 纹理含 mipmap 约 97.3 MiB（RGBA8 估算）。没有增加逐砖模型、额外灯光或逐帧 CPU 纹理计算。

法线加强版同时重制源高度与材质增益：马赛克砖边高度 2.4 mm、釉面砖 3.2 mm、石灰岩板缝 3.0 mm，叠加釉面缓拱、微起伏及石材孔隙。着色器 normalScale 分别为马赛克 1.85、釉面砖 2.10、灰泥 1.25、石灰岩 2.00、水磨石 1.65。数值表示相对源法线 XY 的放大系数；最终感知强度还取决于源高度与入射光角度。

过滤后的法线长度用于估算高频细节方差，适度增加远处高光的粗糙度，以减少深法线的闪烁；湿润釉面变光滑，粗糙砖缝与孔隙仍保留哑光。细节分辨率提高使纹理显存估算增加约 52 MiB，但不增加采样贴图数量、几何面数或绘制批次。

重生成素材：`python scripts/generate-pool-surfaces.py`，需要本机已有的 numpy 与 Pillow。实际尺寸及高度范围见素材目录中的 manifest.json；法线方向、打包约定和导入说明见同目录 README.md。贴图总览：`art/poolcore-sample/pool-surface-palette.png`。

## 视觉与实现边界

建筑材质没有自发光。室外太阳穿过真实侧窗和天窗，使用单张静态阴影图；当前建筑与静态设施已导入 Blender，使用 Cycles 烘焙的漫反射间接光及受遮挡的天空光，加上极弱补光。此烘焙对应当前泳池优先布局，未复用旧 Blender 模型的 EXR。反弹光保存为顶点数据，直射光与水面焦散继续实时计算。

焦散与水面共用波形及脚步扰动。首段采用世界空间接收图和真实池底深度，通过有界高度场迭代估算折射光线落点，以面积变化近似聚光能量；替换了原固定 0.9 m 接收平面。垂直池壁和台阶侧面仍是近似，不能等同任意几何上的完整光子追踪。折射颜色与深度取样一致，并对视线光程作修正。远端一扇低饱和彩窗保留为局部点缀。

窗边光束位置取自实际窗口，在有限体积内进行 4/6/8 步积分，由场景深度遮挡。远景使用极淡的蓝白指数距离雾。默认 Bloom 0.22，配合轻暗角。光球和星尘移出主池首段，仅在远端保留少量；光球高/均衡档 1 个、低档关闭，没有为光球配置额外灯光。

## 性能策略与验证

- 建筑源数据先剔除内部面、合并共面表面，再经 Blender 细分、烘焙并导出为空间批次。网页加载约 5.5 MB 的 Meshopt GLB，共享材质与贴图；其他设施继续按现有程序生成与合批。
- 地形与碰撞使用 8 m 空间桶查询，避免每次移动扫描全地图。
- 八区泳池焦散图集：精致 1536² / 20 Hz，均衡 768² / 15 Hz，流畅 384² / 10 Hz；每次按距离更新最多 2/1/1 区。
- 所有池面共享一次折射/深度捕获。三档水位各自保留反射纹理与正确镜像平面，每次捕获最多更新一个镜面：优先最近水池，邻近其他水位分时更新。三个画质档均保留平面反射。
- 静止镜头按 30/24/15 Hz 更新捕获；镜头移动立即更新。水波、星尘和呼吸光球继续每帧执行。
- 精致档 DPR 目标 1.5–2，最多约 829 万渲染像素；均衡 DPR 1.25，最多约 369 万像素；流畅 DPR 0.8，最多 160 万像素。大窗口受像素预算限制；保留自动降档。精致/均衡/流畅后期 MSAA 为 4/2/0。
- 阴影仅在必要时更新；主场景只有一盏投射阴影的太阳。
- 低档 40 粒子、均衡 90、高档 160；局部体积光依画质使用 4/6/8 步。

开发模式控制台可读取 `window.__poolPerformance`。仅在页面可见且获得焦点时记录有效 FPS 与 P95 帧间隔；无效时为 null。60 FPS 对应平均帧间隔约 16.7 ms，还需结合 P95 判断卡顿。

## 桌面版（Electron）

`npm run build` 之后，同一份产物可以直接用 Electron 打开：

| 命令 | 用途 |
| --- | --- |
| `npm run desktop` | 构建并启动桌面窗口，加载 `dist/` |
| `npm run desktop:dev` | 连接开发服务器；先在另一个终端运行 `npm run dev` |
| `npm run desktop:pack` | 打包成单文件 exe，输出到 `release/` |

窗口通过 `pool://app/` 自定义协议读取 `dist`，因此 `/assets` 绝对路径、模块脚本和 localStorage 都按原样工作，不需要把 Vite 的 base 改成相对路径。F11 切换全屏，F12 打开开发者工具；窗口大小与位置保存在用户目录的 `window.json`，失焦时自动释放指针锁定，聚焦时阻止显示器休眠。

`electron/main.cjs` 是主进程，`electron/preload.cjs` 只暴露平台信息。`electron . --shot` 会在启动 18 秒后截一帧到 `.work-backup/electron-shot.png` 并退出，用于无人值守检查。

## 双击启动

仓库根目录有三个批处理，双击就行，不必开终端：

| 文件 | 用途 |
| --- | --- |
| `启动游戏.bat` | 打开桌面窗口；`dist` 比源码旧时先自动构建一次 |
| `开发模式.bat` | 起 Vite 开发服务器并连上，改代码即时热更新 |
| `打包exe.bat` | 构建后打包便携版 exe 到 `release/` |

`启动游戏.bat` 用 `scripts/needs-build.mjs` 比较 `dist/index.html` 与 `src`、`index.html`、`story.html`、`vite.config.ts`、`package.json` 的修改时间，只有确实过期才跑构建，日常启动是秒开的。三个脚本都会先清掉 `ELECTRON_RUN_AS_NODE`，否则 Electron 会被当成 Node 进程执行并立刻退出。
