# 以泳池为中心的池核改进计划

> 2026-11-06 方向修订：泳池作为尺度锚点保留，但探索主体扩大为被水贯通的建筑。避免重复“矩形池盆＋完整干岸”。剧情翼已改为低顶入口、错轴拱口、曲墙和偏置高井的浅水回路；七区末端扩建已改为从第二出口回接旧区的连续涉水环。两者使用 Blender/Cycles 建模与烘焙，实时水波、折射、焦散继续由 Three.js 计算。外部采光呈乳白封闭光源；不以蓝天风景解释建筑。玩家视角增加可关闭的轻微镜头边缘畸变。下文保留历史方案，冲突处以本段和用户最新要求为准。

记录日期：2026-11-04。状态：开源研究已完成；首段“主泳池—下水台阶—转角水道”已实施，见 [实施记录](POOL_FIRST_IMPLEMENTATION.md)。以下保留整体设计目标，其余远端改造与完整游泳/声音能力不代表已经完成。

## 2026-11-06：以浏览器画面校准 Blender 参考

**上一轮复审更正（用户指出交付截图不合格后）：技术构建通过，视觉验收未通过。** 以下实施项仅记录代码和资产变化，不等于效果达标。实际入口截图仍有整体灰绿、釉面感弱、水体读感偏平、门洞亮部泛白的问题；高井截图大面积亮白，墙、水与顶棚的层次不足，水边仍可见零碎亮点。前后截图还改变了视角，因此不能当作严格控制变量的画质对比。后续须固定机位、FOV、视口与参考版本，再核对实际游戏结果；不得用自行生成的 Blender 参考替代最终实机验收。

此前离线样图与实机并非同一套外观设置：样图使用 0.2 m 方砖、细缝、AgX，实机使用 0.24 × 0.12 m 墙砖和 ACES；实时方向光、环境漫射又叠在 Cycles 完整漫射烘焙上，压平了门洞与阴角的明暗。水线还叠加了不受遮挡的亮边。不能将这些实施偏差解释为实时引擎的必然限制。

- `src/story/bathLook.json` 统一参考渲染与实机的砖尺寸、釉面参数、52° 垂直视角及 +0.5 EV 曝光；浅水廊预览机位与实际行走眼高统一。
- 封闭浅水廊采用 Cycles 烘焙的漫射照明，按保存曝光恢复能量，避免额外太阳和全局环境漫射洗掉空间遮挡。玩家手电仍实时生效；釉面反射与水面反射继续实时计算。
- 弯月面的几何高度和法线坡度统一为 2.5 mm / 18 mm 曲线；移除额外发亮项。暗角改为轻微中性遮光，避免整屏被青色滤层污染。
- 拱门由连续 U 形轮廓挤出，移除分段棱柱的内部端面；重新在 Blender/Cycles 中烘焙，并扩大 UV 岛间距与边缘填充。
- 验收展示使用 `art/sunlit-hall/browser-*.jpg` 的真实 WebGL 截图。`bath-loop-*.png` 仍标为 Blender 离线参考，水的体积路径追踪、釉面多次反射和降噪与实时近似仍有差异，不应混作实际游戏效果。

本轮不添加景深或实时路径追踪。标准档 2× MSAA，性能降档时关闭；保留既有自适应分辨率和反射更新预算。60 FPS 仍需在玩家设备与实际走动中确认，不能用静帧推断。

验证记录：Cycles GPU 建模/烘焙与入口参考帧输出成功；TypeScript、Vite 和离线剧情打包通过。浏览器核对入口、高井及一次短距离涉水移动，捕获的控制台错误为空。真实截图保存为 `browser-low-before.jpg`、`browser-low-after.jpg`、`browser-well-after.jpg`。当前仍有差距：实时釉面使用近似反射探针，水下侧墙光照从俯视照明采样估计，不能重现 Cycles 全部反射与深浅层次；本轮没有做全流程玩法回归或性能基准测试。

## 2026-11-06 后续：入口样板的 HDR 光照与反射

本轮只将剧情浅水廊作为校准样板。参考固定为 `art/sunlit-hall/bath-reference-v1.blend` 和 `reference-v1-low.png`，不随实机调整重新美化参考。入口机位、52° 垂直 FOV、1280 × 720 对照视口与 +0.5 EV 保持一致。实机校准链接为 `/story.html?preview=pool&view=low-entry&calibrate=1`；此模式关闭镜头畸变、Bloom 与 CSS 暗角，保留真实水波。普通试玩去掉 `calibrate=1`。

- 独立烘焙建筑墙体与顶棚两张 2048²、RGB 16-bit EXR，保留线性 HDR 能量。局部有效密度分别约 38 / 34 texels/m，原全建筑共享 JPG 在这些部位约 5.6 texels/m。UV0 用于光照，UV1 保留 Blender 的米制瓷砖坐标；修正 EXR 数据与 glTF UV 的纵向约定。
- 烘焙照明时断开瓷砖的毫米级凹凸，使用平滑表面法线。每个光照像素约 3 cm，无法解析毫米砖缝；把微凹凸烘进去会出现欠采样斑驳。导出模型和反射探针前恢复参考材质，实时瓷砖着色器负责砖缝与釉面法线。
- Cycles 256 samples、间接光限幅 4。静态光照图保留平水面的折射透光、关闭反射焦散路径；波动聚焦由实时共享波场提供，避免把高方差水光永久烘焙成污斑。水体仍参与遮挡与吸收。尝试完全关闭折射焦散曾导致池底失去透射照明，该方案未采用。
- 三个真实房间 HDR 探针经 PMREM 过滤、分区混合并做盒体视差修正。入口主要墙面的窄釉面反射使用额外平面捕获，宽粗糙反射仍使用 PMREM。Blender 面光源用仅反射相机可见的发光代理表示；防止反射目标同时被采样的反馈错误。
- 浅水廊增加带深度的水下场景捕获和扩大的视场边界，折射射线采样实际墙、阶梯、照明；其他场景保留原方案。运行时仍是屏幕采样与解析交点结合，并非逐像素路径追踪。
- 从本机 Blender 自带 OCIO 导出 AgX/sRGB 的 65³ 半浮点 LUT，经对数整形采样，统一显示变换。WebGL 采用 RGBA16F，避免不受支持的 RGB 半浮点内部格式。此 LUT 是有限精度近似，不能把两种渲染器的光传输变成相同。
- 反射背景使用参考的世界辐射值 `[0.1584, 0.1656, 0.1548]`，避免旧高亮天空从水面裁切边缘漏成白线。浅水廊不再叠加参考中不存在的方向光和更衣区点光，玩家聚光手电保留。
- 在线构建将 HDR 资产独立输出、按剧情模块加载和缓存，避免塞进巨大的 JS 字符串。离线 `dist/story.html` 仍内嵌资产，支持原有离线打开方式。

运行时仍有显存与额外捕获成本：光照图约 64 MiB 基础 RGBA16F 显存，外加反射、折射、探针及后处理。保留反射尺寸上限、静止时捕获节流和动态分辨率；未做持续帧率基准，不宣称已达到全场景 60 FPS。拱面釉质、水面微法线、局部探针遮挡和复杂折射仍与 Cycles 有差异。不能仅凭入口对照通过就认定全部关卡或七区完成同等画质。

最终复查记录：TypeScript、Vite 与离线剧情打包通过。浏览器使用固定入口机位及短距离涉水检查，实机对照保存为 `art/sunlit-hall/browser-hdr-entry.jpg`，近景保存为 `browser-hdr-near.jpg`。右墙窗形高光、前暗后亮的空间层次与水底透射已接入；原先粗大的水线白色闪条消除。**仍未达到与 Cycles 相同的视觉质量**：拱门内侧近看仍有残留斑驳，左墙存在探针近似带来的反射差异，水面微细节更碎。调整烘焙采样与微法线并没有彻底消除这些近景问题，后续不得据此宣称全部视觉缺陷已修复。当前状态是可试玩的校准样板，未完成全关卡画质验收。

## 1. 设计中心与纠偏

场景首先应被识别为一个空无一人、向未知处延伸的泳池空间。水池、池沿、水深与身体接近水面的感受构成主体。墙、柱、顶棚负责围合、采光、遮挡与路径提示。

当前问题：3.60 m 跨池桥、6.48 m 第二层桥廊及其栏墙过多占据主体画面；高差主要发生在楼层和高架通道上，泳池被压成建筑底部的水面。此前把“纵深与高度变化”过多落实成了楼层叠加，需要纠正。

保留用户约束：既有 UI 布局；自然阳光穿过实际开口；建筑不自发光、漫射较少；约 8 分钟晨昼暮；多种贴图和已加强的法线；有限且真实可达的连通场景；避免过多测试。用户允许为效果按需使用库和包，选型以兼容性、许可证、实际收益和运行开销为依据。

## 2. 重新阅读的依据

- [Jared Pike / Dream Pools](https://www.jaredpike.art/projects/dream-pools/) 以无尽泳池环境探索梦与现实、怀旧与不安。[作者访谈](https://scare-me.beehiiv.com/p/interview-artist-jared-pike-on-dream-pools-and-the-allure-of-liminal-spaces) 强调眼部/腰部附近的相机、灰模构图、日照与暗部、转角遮挡，以及想象人在水里漂浮时还能去往何处。
- [POOLS 官方](https://poolsthegame.com/) 强调探索、环境声音、不同房间的回声与水中缓行。[官方图片集](https://poolsthegame.com/media/) 作为池体、岸边及贴水视角参考。
- [Dreamcore / Dreampools](https://www.dreamcoregame.com/) 将坡道、楼梯和走廊作为室内泳池之间的连接方式。连接设施围绕水域组织。
- [后室 Wikidot Level 37](https://backrooms-wiki.wikidot.com/level-37) 描述互通水域、瓷砖、异常尺度与没入水中的台阶；[Level 0](https://backrooms-wiki.wikidot.com/level-0) 提供重复、空旷与迷向的空间语法。这些是社区创作设定，不视为所有池核作品统一遵守的规则。
- [Diel 与 Lewis，2022](https://doi.org/10.1016/j.jenvp.2022.101844) 的研究将建筑怪异感与偏离熟悉结构模式联系起来。本项目据此采用“先有可辨认的泳池，再有少量尺度、用途和连接异常”的设计取舍。

以下尺寸、组织和验收条件是本项目的设计目标，不是从参考作品实测得到的数据。参考作品仅供视觉研究，不作为已获授权的项目资产。

## 3. 优先释放主池

- 优先移除横跨主池的 3.60 m 桥面、6.48 m 第二层桥廊和相应栏墙。
- 减少或移走挡住池盆主要轮廓的粗柱；局部高台仅在有清晰观池作用时保留。
- 主视角前方出现连续十几米的水面，近处池沿、入水台阶和远处转角延伸同时可读。
- 大空间的空白留给水面、光影和倒影，不再用额外结构填满。

## 4. 从池盆、岸线和入水方式开始建模

基础数据从房间/楼板优先转为池盆/岸线/水域连接口优先。池盆定义轮廓、池底剖面、岸边高度、下水台阶与干湿连接；可见几何、碰撞、水深查询和水域遮罩由同一数据导出。

首批房型：

1. 开阔长方形主泳池：完整池沿、浅端和深端。
2. 宽台阶浅水池：可以缓慢涉入，踏步在水下仍清楚可读。
3. 转角小水池：需要移动后才能看见全貌。
4. 低顶狭长水道：水面延伸到阴影中，形成压缩与释放。
5. 局部深水侧池：台阶逐渐消失在水色中，作为少量异常。

少量扶手、排水槽、池底标线或深度标记建立人体尺度；不铺满装饰和设施。

## 5. 高度变化围绕水深与池岸

主要变化放在池底坡度、下沉池坑、水下台阶、浅水平台、低岸以及池室净高。

初版相连水域共用一个水位，通过池底变化形成深浅；独立高低水位及跌水属于后续按效果评估的扩展。保留既有共享反射机制，避免为每个池室增加完整反射捕获。

当前角色控制器以地面步行为主。深水可进入之前，必须补上浅水减速、简洁浮游与水深响应：浅处涉水，深处保持稳定水面视角，出水经台阶衔接。避免人在深池底部仍像走地板一样移动。先保证岸边绕行和下水台阶可用。

## 6. 水域连接与阈限感

第一组空间关系：入口干岸 → 主泳池 ↔ 低顶浅水弯廊 ↔ 天光小池 ↔ 深水侧池 ↔ 主泳池。

- 在一个池边只看到下一个池的一部分；先以水面、倒影、局部日照或声音透露入口。
- 重复相似开口，但在池深、净高和光线方面保持细微区别。
- 每区保留一个可记忆特征，有限环路真实可达；未知感来自遮挡和连接，不等同于无限随机生成。
- 不将多楼层、更多柱子或更多网格房间当成质量指标。

## 7. 光、水与材质

太阳优先照到局部水面、入水台阶和附近浅色墙体，同时保留可读暗部。晨昼暮主要通过水面反射、暖冷变化和天空体现；雾控制远处空间，不遮掉主池。

水体重点：岸边透出砖和踏步；深处通过光程吸收表现深度；斜视时可读窗洞与墙面倒影。墙/顶反射水光应受太阳、水域与遮挡约束，不能成为恒定自发光。

复用已有五套 PBR 材质和加强法线：瓷砖、马赛克用于池体，石材用于池沿，水磨石用于干岸，灰泥主要用于顶棚和干区。主厅弱化光球、星尘和彩窗装饰，特殊偏厅后续再集中少量使用。

## 8. 首个交付与实施顺序

第一份可运行交付只完成“主泳池—下水台阶—转角水道”。

1. 池盆与岸线灰模，移除主厅高架遮挡，建立完整水面。
2. 固定岸边、下水台阶和贴水转角三个实际视角，以构图决定墙、柱和开口。
3. 水深与自然光关系；再处理焦散、反射和材质细节。
4. 岸边与台阶通行、水中移动和出水过渡。
5. 样段达到方向后，再将同样的池体规则扩展到其他区域。

技术接入顺序：池盆数据/布局 → 建筑外表面与碰撞 → 水深/水面遮罩 → 波纹与光学 → 角色水中响应 → 声音和局部细节。库仅在明确解决某一步的问题时接入。

## 9. 验收与验证范围

- 开场画面不依赖文字即可识别为室内游泳池。
- 主视线能看到连续的主体水面，未被桥廊与栏墙横切。
- 池沿、入水踏步和浅深变化可读。
- 转角给出下一片水域的线索，同时遮住全貌。
- 高度变化首先体现在池底、台阶和低岸。
- 三个固定视角均成立，样段连接实际可走通。
- 必要构建、一次短通行检查、少量固定视角截图；性能仅做有代表性的前台短测，不由后台截图推断稳定 60 FPS。
